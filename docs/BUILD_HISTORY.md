# Build History — what has been delivered, and why each piece is shaped that way

**This file is a record, not an instruction.** It holds the delivery history that used to live in
`CLAUDE.md`'s Status section. It was moved for one concrete reason: that section had grown to
roughly two thirds of a file every session loads in full, and — worse — it was one of **four**
places claiming project status, which is how the readiness board came to describe a shipped module
as missing for a day. Status now has fewer owners:

| Question | Answer lives in |
|---|---|
| What are the rules I must follow? | `CLAUDE.md` |
| What is still to build? | `docs/REMAINING_WORK.md` |
| What was built, and why is it shaped this way? | **this file** |
| Can this machine place a live order right now? | `python -m runtime.mvp_runtime.crypto.live_readiness` (computed, never prose) |

Nothing here was rewritten or summarised on the move — the entries are verbatim, because their
value is in the reasoning, not the headline. Read it when you need to know *why* something is the
way it is before changing it; a surprising amount of what looks like an odd choice is a recorded
decision with a failure behind it.

Append a new entry when a milestone ships, in the same PR.
