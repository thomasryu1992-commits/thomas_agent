1 – 10위에서는 지금 디스크의 자료로 고를 팩터가 모두 닫혔거나 선별 중이다(§145 뒤의 표). 그래서 Thomas가 선별 결과를 기다리는 동안 거래소 입출금을 물었다. 근거가 있는 쪽은 각 코인의 입출금보다 **USDT가 거래소로 순유입되는 흐름**이다. 이 문서는 그 자료를 과거(2020 – 2024)와 앞으로 어떻게 모을지만 정한다.

## 2. 무엇이 어려운가

- **조회는 쉽다 [문서].** Etherscan 무료 API는 초당 3회, 하루 10만 회이고 여러 체인을 덮는다. 키가 필요하다. 트론은 따로다(TronGrid · TronScan, 조건 [모름]).
- **거래소 주소가 어렵다.**
  - Etherscan의 거래소 라벨 API는 유료 최상위 요금제(Pro Plus · Enterprise)뿐이다 [문서].
  - 무료 후보: Dune의 공개 저장소 `duneanalytics/spellbook`에 체인별 거래소 주소 목록이 있다(`…/_sector/cex/addresses/chains/`, 이더리움 · 트론 · 비트코인 · 솔라나 · 리플 등) [확인: GitHub API, 2026-11-23].
  - 그 저장소의 라이선스는 **Business Source License 1.1**이다 [확인]. 연구에 쓸 수 있는 범위(추가 이용 허락)는 아직 읽지 않았다 [모름].
- **입금 주소.** 거래소는 사용자마다 입금 주소를 만든다. 핫 · 콜드 월렛만 보면 유입이 다 잡히지 않는다. 입금 주소에서 핫월렛으로 모으는 흐름을 어디까지 따라갈지는 정해야 한다 [추정].
- **양.** 큰 거래소의 핫월렛은 USDT 이체가 수백만 건일 수 있다 [추정]. 무료 API의 한도로 5년을 받을 수 있는지는 세어 봐야 안다.
- **그때 알려진 주소.** 지금 아는 주소로 2021년을 재면, 나중에 밝혀진 주소가 섞인다. spellbook은 git 이력이 있어 주소가 목록에 들어온 날을 알 수 있다 [확인: 이더리움 파일의 이력이 2024-07부터 있다. 그 앞의 경로는 [모름]].

## 3. 과거 되짚기 (A)

- **A1 라이선스.** spellbook의 BSL 1.1 본문과 추가 이용 허락을 먼저 읽는다. 연구 용도가 허락되지 않으면 그 목록을 쓰지 않고 멈춘다.
- **A2 주소 목록과 날짜.** 이더리움 · 트론의 거래소 주소를, 목록에 처음 들어온 커밋 날짜와 함께 적는다. 날짜 t에는 t 이전에 목록에 있던 주소만 쓴다.
- **A3 시험 (개수만, 수익은 읽지 않는다).** 바이낸스의 주소 몇 개로 한 달치 USDT 이체를 받아, 건수와 API 요청 수를 센다. 그것으로 5년치에 드는 요청 수와 날 수를 셈한다.
- **A4 멈춤의 줄 (세기 전에 적는다).**
  - 5년치가 무료 한도의 절반(하루 5만 회) 아래로 30일 안에 받아지지 않으면 과거 계열은 멈춘다.
  - 그때 다른 길(Google BigQuery의 공개 이더리움 자료 등, 새 출처)은 Thomas에게 따로 묻는다.
- **A5 값.** 거래소 묶음마다, 그리고 합쳐서, 하루(00:00 UTC 마감)와 1시간의 USDT 순유입(들어온 것 − 나간 것)을 낸다. 거래소 사이의 이동은 빼는 것을 기본으로 한다.

## 4. 앞으로 모으기 (B)

- A2의 주소 목록으로 매일 새 이체를 받아 덧붙인다. spellbook 목록의 변화도 주 1회 받아 새 주소를 날짜와 함께 더한다.
- `claude` 계정의 cron, 제 PR로 짓는다(언락 수집과 같은 꼴). 키는 Thomas가 만들고, 값은 기록하지 않는다(비밀은 메타데이터만).
- 새 네트워크 읽기라 연구 샌드박스의 "비밀 있는 수집" 쪽에 둔다(`RESEARCH_SANDBOX_V0.1`). 운영 런타임의 환경 관문 목록과는 다르다.
